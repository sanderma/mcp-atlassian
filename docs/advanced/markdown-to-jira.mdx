Agents talk to this MCP server in **standard Markdown (GFM)**. On Jira
Server/Data Center, every rich-text write (descriptions, comments,
worklog and transition comments) is translated to Jira wiki markup, and
every read is translated back to Markdown. On Jira Cloud the write path
produces ADF instead and is not covered here.

All conversion logic lives in `src/mcp_atlassian/preprocessing/jira.py`.

> **Maintenance contract:** any change to the conversion behavior must
> update this page, the exact-output unit tests, and the rendering
> corpus in `tests/e2e/test_markup_rendering_dc.py` (see
> [Validation](#validation)). AGENTS.md enforces this for agent-driven
> changes.

## Why this is hard

Jira wiki markup has **no formal specification**. The only reference is
the "Text Formatting Notation Help" page each instance serves; the real
authority is the renderer implementation, whose behavior is quirky and
version-dependent. Three properties make naive conversion corrupt text:

1. **Effects fire inside monospace.** `{{...}}` is a text effect, not a
   literal span: macros (`{panel}`), emphasis, strikethrough, links,
   images, and citations all still execute inside it.
2. **Backslash escaping is unreliable.** `\{` works for a single brace,
   but `\{\{x\}\}` still becomes monospace, and escapes inside
   `{{...}}` render as literal backslashes.
3. **HTML entities always work in text.** `&#123;` renders as `{` in
   prose, headings, table cells, and inside `{{...}}` — but **not**
   inside `{code}`/`{noformat}` blocks (literal there) or bare URLs.

The escaping strategy below was **derived empirically** against a live
Jira DC 10.3 renderer, not from documentation.

## Write path: Markdown → wiki markup

Pipeline (`markdown_to_jira`):

1. **Protect Jira passthrough syntax** — `[~mentions]`, `{anchor:name}`
   and Jira-style nested list lines (`** item`, `*# item`) are
   placeholder-extracted and restored verbatim at the end.
2. **Protect pipes in code spans on table rows** — GFM splits cells on
   `|` before inline parsing; pipes inside backtick spans are
   pre-escaped as `\|` so the span stays in one cell.
3. **Normalize list indentation** — agents commonly nest with 2 spaces;
   CommonMark requires the parent's content column, so indentation is
   re-mapped before parsing.
4. **Parse as CommonMark** with [mistletoe](https://github.com/miyuchina/mistletoe)
   and render with a customized `JiraRenderer` (all rules below).
5. **Join split lists** — a blank line ends a list in Jira, so two
   adjacent lists cannot be represented; CommonMark splits `- \n- x`
   into exactly that (an empty item, then the rest), and rendering the
   split faithfully put a blank line inside what Jira reads as one list.
6. **Repair intraword emphasis** — CommonMark parses `2*3*4` as
   emphasis, which Jira cannot render intraword; the author's literal
   characters are restored as backslash escapes (`2\*3\*4`). Code
   blocks, monospace, links, images, and URLs are shielded from this
   repair.

On any parser error the original Markdown is returned unchanged —
conversion never destroys content.

### Construct translation

| Markdown | Jira wiki markup |
|---|---|
| `# H1` … `###### H6`, setext | `h1.` … `h6.` |
| `**bold**` / `*italic*` / `~~strike~~` | `*bold*` / `_italic_` / `-strike-` |
| `` `inline code` `` | `{{...}}` with full entity encoding (see below) |
| ` ```lang ` fenced / indented code | `{code:lang}` — language normalized to Jira's supported set (`typescript`→`javascript`, `dockerfile`→`bash`, unknown → plain `{code}`); `yaml`/`yml` also fall back to plain `{code}` (see below); content containing `{code` uses `{noformat}` instead |
| Lists (`-`/`*`/`+`, `1.`/`1)`, nested, mixed) | `*` / `#` runs (`**`, `##`, `#*`, …) |
| `> quote` (single line / multi-line) | `bq.` / `{quote}…{quote}` |
| `[text](url)`, reference links, autolinks, titles | `[text\|url]` or `[text\|url\|title]` |
| `![alt](url)` | `!url\|alt=alt!` (alt sanitized: `!`, `\|`, `,` removed/replaced) |
| GFM tables (alignment rows, escaped pipes) | `\|\|header\|\|` / `\|cell\|` rows |
| `---` horizontal rule | `----` |
| Hard break / `<br>` | `\\` (in table cells: `\\` without newline, so the row survives) |
| Soft break | kept as newline (Jira preserves single newlines) |
| Inline HTML `<sup>` `<sub>` `<ins>`/`<u>` `<del>`/`<s>` `<cite>`/`<q>` `<b>` `<i>` | `^x^` `~x~` `+x+` `-x-` `??x??` `*x*` `_x_` |
| `<span style="color:red">` / `<font color=…>` | `{color:red}…{color}` |
| `[~user]`, `[~accountid:…]`, `{anchor:name}`, `** nested` Jira lists | passed through verbatim |

### Escaping rules (renderer-verified)

| Context | Characters | Mechanism |
|---|---|---|
| Prose `{` `}` | always | HTML entity (backslash provably fails on doubled braces; spaced `{ x }` splits the paragraph) |
| Prose `*` `_` | when touching non-whitespace | backslash (older Jira applies emphasis intraword — snake_case italics; escapes render clean, and the read path can invert them) |
| Prose `-` `+` `^` `~` | only at word-boundary positions | backslash — `well-known`, `2024-01-15`, `C++`, `x^2` stay readable |
| Prose `[` `]` | always | backslash — brackets only ever mean link markup to Jira, and the neighbour that would justify leaving one alone can sit in the next inline token, out of the escaper's sight (`text [` and `](url)` arrive separately) |
| Emoticons `:)` `:(` `;)` `:P` `:D` (also lowercase `:p` `:d`) `(y)` `(n)` `(i)` `(/)` `(x)` `(!)` `(?)` `(+)` `(-)` `(*)` `(*r)` `(*g)` `(*b)` `(*y)` `(on)` `(off)` `(flag)` `(flagoff)` | exact tokens | first character becomes an entity — displays identically (`f(x)` stays `f(x)`), Jira's icon substitution is stopped |
| Line-start tokens in paragraphs: `h1.`–`h6.`, `bq.`, `\|`, `--` runs | first line and soft-broken continuation lines | entity on the recognizing character (`h2&#46;`) |
| Inline code content | **everything**: `&` `{}` `[]` `*` `_` `-` `+` `^` `~` `\|` `!` `?` | HTML entities — the only representation Jira passes through verbatim inside `{{...}}`; `&` first so pre-existing entity-like text stays literal |
| Bare URLs | none (escapes break Jira's autolinking); `{` `}` → `%7B`/`%7D` (Jira macro-parses braces even inside URLs) | percent-encoding |
| Link text | `\|` → `&#124;` (the alias separator cannot be escaped) | entity |
| Table cell text | literal `\|` → `&#124;`; structural pipes from `[text\|url]` links untouched; a cell also *opens a line*, so `h1.`–`h6.`, `bq.`, `--` are neutralized there too | entity |
| Link text (`[alias\|url]`) | `\|` → `&#124;`, `!` → `&#33;` (Jira runs image markup inside a link alias) — applied to author text only, so a nested image keeps its own delimiters; a leading `^` is backslashed (`[^name]` is attachment-link syntax) | entity |
| Link / image target | percent-encoded, including `[` `]` `\|` `{` `}`. The stock renderer backslash-escapes brackets; Jira strips the backslash, the read path keeps it and the next write encodes it, so the URL grew a `%5C` per edit cycle. An empty target is not a link at all — `[text\|]` is not markup, and the stray pipe splits a table cell | percent-encoding |
| Image alt | `!` `\|` `,` removed (they end or split the markup); `&` `{` `}` `[` `]` → entities (a macro in the alt terminates the image) | strip + entity |
| Literal backslash anywhere in prose | always → `&#92;` | entity — see below |
| Code block content | nothing — `{code}` content is literal | — |

#### Why every backslash becomes `&#92;`

Jira treats a backslash as an escape and **drops it** in front of

```
! # % ( ) * + - ? @ [ ] ^ _ { | } ~
```

and keeps it in front of everything else. That set was probed character
by character against the DC 10.3 renderer; it is also what the read path
inverts. Two consequences make a "only encode when needed" rule
unworkable: whether a backslash is followed by one of those characters
depends on the *rendered* neighbour, not the one in the same Markdown
token, and a backslash at the end of a table cell escapes the closing
`|` and merges the cell with the next one. `&#92;` displays as `\` in
prose, headings, list items and cells alike, so it is used everywhere.

### Known degradations (unrepresentable in Jira)

- **Attached superscript/subscript**: `mc<sup>2</sup>` renders as
  `mc^2^` caret notation — Jira's `^x^`/`~x~` require word boundaries.
- **Intraword emphasis**: `2*3*4` displays as the literal characters,
  not italic "3".
- **Code containing both `{code}` and `{noformat}`**: kept as `{code}`;
  Jira offers no escaping inside either block.
- **YAML highlighting**: Jira's YAML highlighter swallows the newline
  after a line ending in a bare `key:`, collapsing a nested mapping onto
  one line — and indentation *is* YAML's syntax. `yaml`/`yml` blocks are
  emitted as plain `{code}`, trading colour for a readable block. Every
  other supported language is swept for the same fault in
  `test_code_block_languages_keep_their_line_breaks`.
- **Multi-paragraph list items**: continuation paragraphs lose their
  list attachment (a Jira list limitation).
- **Image parameters**: `thumbnail`, `width`, `align` and friends are
  dropped on read — Markdown has nowhere to put them. The alt text and
  the source survive.
- **Images whose URL contains `!`**: dropped in favour of the alt text.
  `!` ends image markup and Jira accepts no encoding for it there, so
  the alternative is markup that swallows the rest of the paragraph.

## Where conversion applies

Every rich-text field is converted in both directions, so an agent sees
Markdown no matter which tool it used to get there:

| Field | Write | Read |
|---|---|---|
| `description` | `jira_create_issue`, `jira_update_issue`, `jira_batch_create_issues` | `jira_get_issue`, `jira_search`, board/sprint issue lists, and the issue returned by every write tool |
| Comment bodies | `jira_add_comment`, `jira_update_comment`, transition comments | `jira_get_issue`, `jira_get_comments`, `jira_search` |
| Worklog comments | `jira_add_worklog` | `jira_get_worklog` |
| Rich-text custom fields (`:textarea`) | `jira_update_issue`, `jira_create_issue` | `jira_get_issue`, `jira_search` |

Single-line custom fields (`:textfield`) hold plain text and are left
alone in both directions.

## Read path: wiki markup → Markdown

`jira_to_markdown` uses [jira2markdown](https://github.com/catcombo/jira2markdown)
(a pyparsing grammar) with custom elements, then a small amount of
pre- and post-processing that exists so the cycle in
[Round-trip stability](#round-trip-stability) holds.

Custom grammar elements:

- **`{code}` / `{noformat}`** — no "Java" default language, and fence
  delimiters sized past any backtick run in the content.
- **`{{monospace}}`** — decodes HTML entities (the write path's
  encoding) and sizes the backtick delimiters the same way.
- **`[~user]`** — kept as the wiki mention. jira2markdown renders
  `@user`, which the write path cannot turn back into a mention, so an
  agent's edit would silently unlink the person.
- **`!url|alt=text!`** — keeps the alt text and drops the rest.
  jira2markdown discards the alt an author wrote and substitutes the
  URL, which the write path then re-adds — growing an `alt=` clause per
  edit cycle. Jira's sizing parameters have no CommonMark form;
  jira2markdown emits a Pandoc `{width=200}` suffix that this renderer
  cannot write back, so it would return as visible text beside the
  image.

Pre-processing (skipped inside `{code}`, `{noformat}` and `{{...}}`,
where a backslash is literal):

- **Lift `\X` escapes** to placeholders. jira2markdown reads that
  backslash as ordinary text and escapes it again, so a literal `*`
  gained one backslash per edit cycle until `\\` — Jira's line break —
  injected a newline.
- **Lift Markdown block openers Jira reads as prose**: `1.`, `1)`, `>`
  and `+` at the start of a line. Jira numbers lists with `#`, quotes
  with `bq.` and bullets with `*`, so those lines are plain text there
  and must not come back as Markdown blocks. A Jira block marker
  (`bq.`, `*`, `#` and their runs) counts as still being at the start of
  the line, because the conversion replaces it with a Markdown one and
  promotes whatever followed.

Post-processing (outside code spans and fences):

- **Restore the lifted characters** as Markdown escapes, chosen by
  position: `\*` mid-sentence, `\+` opening a line, `1\.` after a
  leading number, `\|` inside a table row. A literal backslash gets a
  trailing space when it would otherwise land against a line ending (a
  CommonMark hard break) or a cell's closing `|` — GFM splits cells on
  any `|` not directly preceded by a backslash, without counting them,
  so `\\|` reads as an escaped pipe and the cell swallows the row.
- **Decode the write path's numeric entities** the same way, so a
  reader sees the character Jira displays.

Results are memoized (LRU), and inputs over 20k characters or parse
failures fall back to a fast regex pipeline. That fallback carries the
same stability guarantee — long descriptions are common on Data Center,
and it is covered by the same corpus. `clean_jira_text`
additionally resolves mentions and smart links and shields Markdown
links, autolinks, and inline formatting tags from the HTML cleanup pass.

### Round-trip stability

Conversion is lossy in one direction — Jira has no Markdown — so the
guarantee is **stability**, not identity:

> After the first write, `markdown_to_jira(jira_to_markdown(markup))`
> must equal `markup`, byte for byte, forever.

That is what makes read-modify-write safe. An agent reads an issue,
edits one line, and writes it back; without stability the untouched
parts of the description drift a little on every edit. It is enforced by
`TestRoundTripStability` (a 68-case corpus, unit), the hazard matrix
(~3 500 token × context combinations), and
`test_round_trip_renders_identically` (the same cycle plus a live
renderer diff of the visible text, e2e). The unit corpus runs twice:
once through the parser, once through the regex fallback.

For arbitrary generated input the property is stated as *bounded
convergence* — the cycle reaches a fixed point and the markup does not
keep growing — because the empty-block shapes below need one cycle more
than the first write.

Known first-cycle losses — stable afterwards, but not reversible:

- `{panel:title=T}body{panel}` becomes a blockquote with a bold title.
- `[Display Name|~user]` keeps the mention, drops the display name.
- Image parameters (`thumbnail`, `width`, …) are dropped; the alt text
  and the source survive.
- A link's title (`[t|url|title]`) is dropped.
- Jira's Confluence-lookalike macros (`{note}`, `{info}`, `{tip}`,
  `{toc}`, …) are literal text in Jira, and are escaped as such.

Two degenerate shapes need a second cycle rather than one, and neither
is worth contorting the converter for — both settle, and neither grows:
a list whose *only* item is empty (Jira writes it as a bare `#`, which
the wiki parser has no list to attach to and returns as a heading), and
a list item whose entire content is `.` or `)` (CommonMark parsers read
that as an ordered-list marker and nest a list inside the item). Both
are pinned by `TestEmptyListItems`.

## Validation

Five layers, run in CI order of cost:

1. **Exact-output unit tests** —
   `tests/unit/preprocessing/test_preprocessing.py` and
   `test_markup_edge_cases.py` (code-block shapes, inline-code shapes,
   link and image shapes, table-cell hazards, escaping rules, empty list
   items, degenerate input).
2. **Structural output linting** —
   `tests/unit/preprocessing/test_jira_markup_validity.py` converts a
   hostile corpus and lints the output for damage (leftover backticks,
   merged braces, unbalanced macros, broken table rows, leaked
   placeholders).
3. **Hazard matrix** —
   `tests/unit/preprocessing/test_markup_edge_cases.py` places each of
   ~60 hazardous tokens in each of ~30 structural contexts (~3 500
   cases) and checks the invariants that must hold everywhere: no
   crash, no leaked placeholder, structurally valid output, stable
   under a read-modify-write cycle.
4. **Property-based tests** —
   `tests/unit/preprocessing/test_markup_properties.py` generates
   Markdown documents with Hypothesis from the same hazardous alphabet
   and asserts: never raises, structurally valid, code content is
   verbatim, nothing is silently dropped, and the edit cycle settles
   without growing. This is the layer that finds what nobody thought to
   write down — the mention pattern that matched across a table cell,
   the URL that grew a `%5C` per cycle, the empty blockquote that
   aborted a whole document.
5. **Real-renderer oracle** — `tests/e2e/test_markup_rendering_dc.py`
   renders 100+ converted cases through a live Jira DC wiki renderer
   and asserts on **browser-visible text** (entity decoding included)
   plus HTML structure and generic invariants. It also runs each
   round-trip case through a full edit cycle and asserts the rendered
   text is unchanged.

Run the renderer suite against the dockerized Jira DC:

```bash
cd tests/e2e/docker
cp .env.example .env
docker compose up -d jira-db jira
bash setup-jira-wizard.sh     # fetches the free timebomb license and
                              # completes the setup wizard - no browser
cd ../../..
uv run pytest tests/e2e/test_markup_rendering_dc.py --dc-e2e -v
```

The wizard also raises Jira's failed-login threshold on the container.
Jira locks an account behind a CAPTCHA after three failed logins, and
REST refuses basic auth for a few minutes after setup while the instance
finishes starting — so every probe in that window counts as a failure and
the account is locked before it is ever usable, with the CAPTCHA
clearable only through the web UI. This applies to the disposable test
instance only; never do it on a real one.

The wizard script obtains Atlassian's **public timebomb license**
(Jira Software Data Center, 10 users, valid 3 hours — free, no account)
via `tests/e2e/docker/get-jira-license.sh`, which you can also run on
its own. Manual copies live on
[Atlassian's testing-licenses page](https://developer.atlassian.com/platform/marketplace/timebomb-licenses-for-testing-server-apps/).
Only Jira is needed for these tests; Confluence can stay down.

When changing conversion behavior: probe the renderer first (the
`/rest/api/1.0/render` endpoint accepts raw wiki markup and returns the
HTML Jira produces), then encode the verified behavior in all three
layers and update the tables on this page.
